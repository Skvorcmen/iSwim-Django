# i.SWiM Django Portal

## О проекте

`i.SWiM` — это веб-портал для управления плавательной школой и соревнованиями.
Он реализован на Django и включает управление пользователями, регистрацию участников, формирование заплывов, результаты соревнований, новости, чат и живые обновления.

## Основные возможности

- Пользовательские роли: `Admin`, `Secretary`, `Trainer`, `Athlete`, `Fan`
- Регистрация и управление соревнованиями
- Процесс заявки и загрузка XLSX с участниками
- Генерация заплывов, добавление участников в heats и ввод времени
- Финализация дисциплин, присвоение мест и DNF-статусов
- Ведение рекордов по категориям, полу и дисциплинам
- Публичные страницы результатов и протоколов соревнований
- Живые обновления через Django Channels / WebSocket
- REST API для соревнований
- Основной поиск и лента активности

## Установка

1. Клонируйте репозиторий
2. Создайте виртуальное окружение: `python -m venv .venv`
3. Активируйте: `source .venv/bin/activate`
4. Установите зависимости: `pip install -r requirements.txt`
5. Примените миграции: `python manage.py migrate`
6. Запустите сервер: `python manage.py runserver`

## Архитектура приложения

Приложение разделено на следующие Django-приложения:

- `users` — кастомная модель пользователя, профили спортсменов, секретарей, тренеров, система ролей и аутентификация
- `competitions` — соревнования, дисциплины, возрастные категории, заявки, heats, результаты, рекорды
- `trainers` — профиль тренера и привязка к филиалам
- `branches` — филиалы школы и их страницы
- `news` — новости, комментарии, лайки
- `academy` — образовательные статьи и контент
- `chat` — простой чат с AJAX и API
- `activity` — запись активности пользователей
- `core` — базовые страницы и поиск

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate

```

2. Примените миграции:

```bash
python manage.py migrate
```

## Публичные страницы профилей

- `http://127.0.0.1:8000/trainers/<pk>/` — тренер
- `http://127.0.0.1:8000/athlete/<username>/` — спортсмен
- `http://127.0.0.1:8000/fan/<username>/` — болельщик
- `http://127.0.0.1:8000/branches/<pk>/` — филиал

## Личные кабинеты пользователей

После входа в систему каждый пользователь может перейти в личный кабинет (`/profile/`), который автоматически перенаправляет на соответствующую страницу в зависимости от роли:

- **Спортсмен** (`/profile/athlete/`):
  - Мой профиль с достижениями
  - Предстоящие соревнования и дисциплины
  - Информация о тренере и филиале
  - Достижения, медали и рекорды
  - Редактирование Instagram и стажа плавания

- **Тренер** (`/profile/trainer/`):
  - Мой профиль с рейтингом
  - Список моих спортсменов
  - Предстоящие соревнования для моих спортсменов
  - Информация о филиалах
  - Контакты и социальные сети

- **Болельщик** (`/profile/fan/`):
  - Избранные спортсмены
  - Соревнования избранных спортсменов
  - Статистика достижений избранных
  - Управление избранными спортсменами

- **Филиал** (`/branches/<pk>/cabinet/`):
  - Информация о филиале
  - Ближайшие соревнования в филиале
  - Список тренеров филиала
  - Список спортсменов филиала
  - Статистика и контакты

## База данных и миграции

- Основная база: SQLite `db.sqlite3`
- Миграции содержат изменения модели `Record`, статус `HeatAssignment`, и создание стандартных групп

## Структура URL

Основные пути:

- `/` — главная страница
- `/activity/` — общая лента активности
- `/activity/me/` — персональная лента пользователя
- `/competitions/` — список соревнований
- `/competitions/<pk>/` — страница соревнования
- `/competitions/api/` — API список соревнований

### API Endpoints

REST API для соревнований:

- `GET /competitions/api/` — список всех соревнований (JSON)
- `GET /competitions/api/<pk>/` — детали соревнования (JSON)
- `GET /competitions/api/<pk>/results/` — результаты соревнования (JSON)
- `GET /competitions/api/heats/<heat_id>/` — назначения на заплыв (JSON)

Все API возвращают JSON данные, оптимизированные для внешних интеграций.

## Ролевая система

- **Secretary**: управление соревнованиями (Django Groups + legacy profile fallback)
- **Trainer**: просмотр и управление спортсменами
- **Athlete**: участие в соревнованиях
- **Fan**: просмотр результатов

## WebSocket обновления

Реалтайм обновления результатов через Channels:

- `/ws/competitions/<pk>/` — обновления для соревнования
- Поддержка delta и full updates для эффективности
- `/competitions/api/<pk>/` — API данные соревнования
- `/competitions/api/<pk>/results/` — API результаты соревнования
- `/competitions/api/heats/<heat_id>/` — API данные заплыва
